# Layout and responsive behavior

**Covers:** 安排内容的位置、尺寸、对齐和滚动，并处理容器、内容或输入方式变化后的重排。

**Use when:** 新建或调整布局；出现密度、对齐、溢出、截断、响应式、多语言或输入方式问题时。

**Does not cover:** 信息主次查 `hierarchy.md`；界面状态和反馈查 `states.md`；颜色、动效分别查 `color.md`、`motion.md`；组件内部尺寸、props、焦点管理和 ARIA 查组件契约。

## 确认布局环境和滚动归属

### Do

- 沿用现有顶栏、侧栏和导航；任务未要求时不重建 Shell。
- 同一工作区、同一方向只设一个主要滚动容器。固定区域使用 `shrink-0`，纵向滚动子项使用 `min-h-0`，横向可收缩子项使用 `min-w-0`。
- 为可调整或折叠的分区明确最小值、最大值、折叠入口和恢复规则；未确认的值标为待确认。
- 确需嵌套同向滚动时，明确边界；内层滚动到边界后，仍能继续滚动外层。
- 固定或 Sticky 区域覆盖滚动内容时，预留对应空间，确保最后一项内容和操作完整滚入视口。

以视口为根的桌面 App Shell 可使用以下结构；嵌入已有定高父级时，将 `h-screen` 改为 `h-full`：

```tsx
<div className="flex h-screen overflow-hidden">
  <aside className="shrink-0">...</aside>
  <div className="flex min-w-0 flex-1 flex-col">
    <header className="shrink-0">...</header>
    <main className="min-h-0 flex-1 overflow-auto">...</main>
  </div>
</div>
```

### Don't

- 不默认套 App Shell、Dashboard、Bento 或卡片网格。
- 不用固定高度掩盖滚动边界不清的问题，也不把 `h-screen` 当成移动端可见高度的通用答案。
- 不叠加边界不清的同向滚动。

### 设计原则

先确认内容位于整页、现有 Shell、面板、抽屉还是 Dialog，再判断主要工作区、辅助区、横纵滚动归属，以及数据量和文字长度范围。

页面默认自然增长。只有父级高度确定，且用户需要在固定工作区持续操作时，才建立内部滚动。

## 选择布局方式

### Do

- 已确认只有一个主要阅读或输入流时，使用 `mx-auto w-full max-w-*` 的限宽单列。
- 已确认是同类入口集合时，从 `grid-cols-1` 开始，空间足够再增列；只有 `hierarchy.md` 已确认的优先入口才跨行或扩大面积。
- 主要工作区优先获得空间，辅助区只保留完成职责所需的宽度。
- 普通内容留在正常文档流；需要超出内边距时，调整容器层级和 padding 归属。

### Don't

- 不因为仓库已有某种模板或组件，就强行使用单列、入口网格、卡片或双视图。
- 宽度按任务和内容分配，不默认等宽。
- 屏幕变窄时，不强行保留双栏；主要任务内容优先，辅助内容下移、收起或按需显示。
- 不照搬旧页面的尺寸和装饰样式。
- 不用负 margin、`calc()` 或绝对定位绕过父级布局；内容确实需要重叠、使用浮层或组件已有定位行为时除外。

### 设计原则

| 方式   | 适用关系                                 |
| ------ | ---------------------------------------- |
| 文档流 | 按阅读顺序自然展开                       |
| Flex   | 一维排列、控件组、主次两栏或剩余空间分配 |
| Grid   | 行列关系同时重要，字段或卡片需要稳定对齐 |

布局方式必须服务当前任务。双视图只有在两种视图分别支持真实的查看、比较或操作需求时才成立；切换后还要保留必要状态。

## 处理间距、圆角和对齐

### Do

使用 Tailwind v3 默认刻度作为起点：

| 关系                 | 常用起点          |
| -------------------- | ----------------- |
| 图标与文字、紧密标签 | `gap-1` / `gap-2` |
| 控件组或字段内部     | `gap-2` / `gap-3` |
| 同一内容分组         | `gap-3` / `gap-4` |
| 相邻分组             | `gap-6`           |
| 页面级区域           | `gap-8` 或更大    |

- 同类关系使用同一档位，组内间距小于组间间距；组件内部 padding 沿用组件契约。
- 紧密嵌套且四周 padding 一致时，使用 `outer radius = inner radius + padding`；计算后从现有 `rounded-*` 中选择最接近的值。
- pill、圆形控件和已有组件沿用组件圆角规则，不使用嵌套圆角规则。
- 按列比较时，文字左对齐，数字右对齐。
- 连续变化且会造成宽度跳动的数值，在组件支持时使用 `tabular-nums`。
- 位数、符号或单位会变化时，按已确认的最长格式为数值容器预留空间。
- 表单标签、输入框和错误提示保持稳定关系；可复用的光学对齐在资产或组件中修正，不在页面反复补 margin。
- Checkbox、Radio 的控件、标签和两者间的空白都应可点击；具体结构沿用组件契约。

### Don't

- 不复制 px 间距或圆角表，不为套公式写任意值。
- 不为整齐强行对齐无关内容，也不靠增加嵌套容器修小错位。
- 不用更紧凑的密度代替信息层级。
- 相邻控件的可交互区域不得重叠；装饰层不得拦截点击或触摸。
- 输入控件可用时，可视边界内不得出现无响应区域；具体点击行为沿用组件契约。

### 设计原则

间距表达关系，不表达重要性。浏览和比较大量信息可以更紧凑；首次引导、阅读和低频配置可以更舒展。密度由任务决定。

## 空间不足时如何布局

### Do

- 使用项目现有 `sm / md / lg / xl / 2xl` 或容器规则。
- 对每个变化区域明确：哪些内容保留，哪些换行、堆叠、滚动、折叠或移入次级入口。
- 重排后让视觉、DOM 和键盘焦点遵循同一任务顺序。
- 全屏移动端验证实际可见区域、safe area、横竖屏和屏幕键盘；超宽屏限制正文、表单和逐项编辑区的行宽。

### Don't

- 不只写“桌面 / 平板 / 手机”，也不用设备名代替重排规则。
- 不用 CSS `order` 或 `grid-area` 单独改变视觉顺序，也不为普通容器批量添加 `tabindex`。
- 不把 `100vh`、固定底部 padding 或任意断点当成通用答案。

### 设计原则

在内容开始拥挤、截断、失去比较关系或让操作不可达时重排。文字增长、容器宽度和输入方式都可能比设备名更早触发变化。

先保留完成任务所需的内容和操作，再决定整组换行、堆叠、折叠或滚动；不要逐项压缩到不可用。

## 工具栏和表格

### Do

确认搜索和筛选属于同一任务组后，工具栏变窄时整组换行，独立操作保持可用：

```tsx
<div className="flex flex-wrap items-start justify-between gap-x-3 gap-y-2">
  <div className="flex min-w-0 flex-1 flex-wrap items-center gap-2">
    <div className="min-w-0 flex-1">...</div>
    <div className="min-w-0 basis-full md:flex-1 md:basis-auto">...</div>
  </div>
  <div className="flex shrink-0 items-center gap-2">...</div>
</div>
```

表格与分页按工作区类型二选一：

```tsx
// 自然内容流
<section className="flex flex-col gap-4">
  <div>{/* table */}</div>
  <div className="flex justify-end">{/* pagination */}</div>
</section>

// 父级高度已确定的工作区
<section className="flex h-full min-h-0 flex-col gap-4">
  <div className="min-h-0 flex-1 overflow-auto">{/* table */}</div>
  <div className="shrink-0">{/* pagination */}</div>
</section>
```

- 窄容器中的表格优先保留列间比较，把横向滚动放在明确的容器上。
- 仅截断不影响当前任务、且另有全文入口的次要内容。

### Don't

- 不继续压缩已失去可用宽度的控件，也不为填满空间增加无关按钮。
- 不默认把窄表格改成卡片。
- 身份、错误原因和完成任务所需的信息不能只剩省略号。

### 设计原则

搜索、筛选和相关控件属于同一任务组时才一起换行。列是否固定、表格是否内部滚动、内容是否截断，都由比较任务和父级空间决定。

## 多语言和长内容

### Do

- 标题、说明、按钮和标签允许在合理位置换行；短标题可用 `text-balance`，短至中等说明可用 `text-pretty`。
- URL、ID、代码和无空格长串应明确选择换行、滚动或复制入口；`truncate` 同时提供非 hover 的全文入口。
- 正文、ID、代码和日志保持可选中。
- 用产品中可能出现的中文、长英文、数字、emoji、空值和本地化文案测试。

### Don't

- 不用固定高度假设文字永远单行。
- 不把 hover 当成查看全文或完成核心操作的唯一方式。
- 不在页面或应用根容器设置 `select-none`；拖拽和手势组件沿用组件契约。

### 设计原则

内容变长是正常情况，不应按异常处理。选择换行、滚动或截断时，先保证内容仍可理解、可比较、可操作。

## 验证布局

### Do

- 从最窄目标宽度到超宽屏连续缩放检查，不只抽查几个设备宽度。
- 分别检查 0 条、1 条和大量数据下的高度与滚动。
- 使用项目声明的文字缩放与间距标准；未声明或未实际验证时标为“未验证”。
- 使用键盘、鼠标和触屏检查核心操作、点击区域和焦点顺序。
- 页面自行管理滚动容器时，让键盘焦点所在元素保持可见，且不被固定区域遮挡；组件内部滚动沿用组件契约。

### Don't

- 不以单张桌面截图或单一示例数据声称布局已经适配。
